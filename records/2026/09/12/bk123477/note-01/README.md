### 1. 숫자 짝꿍: `defaultdict`와 `Counter`

현재 풀이는 `defaultdict` 두 개에 `X`, `Y`의 숫자별 등장 횟수를 저장하고, 숫자별 최솟값을 다시 `common_dict`에 기록한다. `Counter`를 사용하면 두 문자열의 카운트를 만들고 `&` 연산으로 각 숫자의 최솟값을 바로 구할 수 있다.

```python
from collections import Counter

def solution(X, Y):
    common = Counter(X) & Counter(Y)
    result = ''.join(str(digit) * common[str(digit)]
                     for digit in range(9, -1, -1))

    if not result:
        return "-1"
    return "0" if result[0] == "0" else result
```

`Counter` 대안은 카운터를 만드는 과정과 공통 개수 계산을 간결하게 표현하지만, 두 문자열을 한 번씩 읽어야 하므로 시간 복잡도는 현재 풀이와 같은 `O(|X| + |Y|)`이다. 숫자 종류가 10개로 고정되어 있으므로 결과 문자열을 제외한 추가 공간도 두 방식 모두 `O(1)`로 볼 수 있다. 즉, 이 경우의 장점은 점근적 성능 향상보다는 의도와 코드를 줄이는 데 있다.

### 2. 햄버거 만들기: 덱 처리와 리스트 스택

현재 풀이는 재료를 `deque`에 넣은 뒤 마지막 네 개를 꺼내 검사한다. 덱의 뒤에서 꺼내므로 햄버거 순서 `1, 2, 3, 1`은 꺼낸 순서 `1, 3, 2, 1`로 뒤집혀 코드에 나타나며, 실패하면 네 원소를 역순으로 다시 넣어 기존 순서를 복원한다.

리뷰 요청에 있는 대안은 리스트를 스택처럼 사용하고, 새 재료를 넣을 때마다 마지막 네 원소만 확인한다.

```python
def solution(ingredient):
    stack = []
    count = 0

    for item in ingredient:
        stack.append(item)
        if stack[-4:] == [1, 2, 3, 1]:
            count += 1
            for _ in range(4):
                stack.pop()
    return count
```

두 방식 모두 이미 처리한 접두부를 다시 탐색하지 않고, 새로 쌓인 위치의 인접한 네 재료만 확인하므로 시간 `O(n)`, 공간 `O(n)`이다. 패턴 길이가 4로 고정되어 있어 대안이 점근적으로 더 빠르지는 않지만, 리스트의 suffix 확인이 문제의 조건을 그대로 보여 주고 현재 코드의 `temp_stack`처럼 사용하지 않는 변수가 없다. 반대로 현재 방식은 덱의 뒤에서 꺼내고 복원하는 과정을 명시해 동작 원리를 드러낸다.

### 3. 크레인 인형뽑기 게임: 전치한 보드와 원본 보드 순회

현재 풀이는 먼저 `board`를 `game`으로 전치해 각 열을 하나의 배열로 만든다. 이후 이동마다 해당 배열을 위에서 아래로 찾아 첫 인형을 꺼내고, 바구니 스택의 마지막 인형과 같으면 두 개를 제거한다. 원본 `board` 대신 전치한 복사본을 수정하므로 입력 보드의 값은 보존된다.

리뷰 요청의 대안은 전치하지 않고 매 이동마다 `board[j][i-1]`를 직접 위에서 아래로 순회한다.

```python
def solution(board, moves):
    stack = []
    answer = 0

    for move in moves:
        for row in range(len(board)):
            if board[row][move - 1] != 0:
                doll = board[row][move - 1]
                board[row][move - 1] = 0
                if stack and stack[-1] == doll:
                    stack.pop()
                    answer += 2
                else:
                    stack.append(doll)
                break
    return answer
```

두 방식의 이동 처리 시간은 최악의 경우 `O(MN)`으로 같다. 현재 풀이는 전치에 `O(N^2)` 시간과 `O(N^2)` 공간을 추가하고, 대안은 전치 비용과 복사 공간을 없애는 대신 입력 `board`를 직접 변경한다. 따라서 입력 변경을 허용하면 대안이 더 단순하고 공간을 절약할 수 있고, 원본 보존이 필요하면 현재 풀이처럼 별도 자료를 만드는 편이 안전하다.
